## 🔬 实践记录

```c
/* blue-pill · 板载 LED 在 PC13，低电平亮 · 寄存器版，不依赖任何库 */
#include <stdint.h>

#define RCC_APB2ENR (*(volatile uint32_t *)0x40021018u) /* RM0008 8.3.7 */
#define GPIOC_CRH   (*(volatile uint32_t *)0x40011004u) /* PC13 在 CRH 的 [23:20] */
#define GPIOC_ODR   (*(volatile uint32_t *)0x4001100Cu)

int main(void)
{
    RCC_APB2ENR |= (1u << 4);      /* IOPCEN：先开门，才写得到 GPIOC */
    GPIOC_CRH &= ~(0xFu << 20);    /* 清掉 PC13 的 4 位 */
    GPIOC_CRH |=  (0x2u << 20);    /* MODE=10 输出 2MHz，CNF=00 通用推挽 */

    for (;;) {
        GPIOC_ODR ^= (1u << 13);   /* 翻转 PC13：低电平亮 */
        for (volatile uint32_t i = 0; i < 800000u; ++i) { } /* 粗延时，别信它 */
    }
}
```

**实际结果**：灯以大约 1Hz 闪；逻辑分析仪量到的周期是 1.08–1.16s 来回飘。把 `volatile` 去掉、
加 `-O2` 重新编译后循环被整个优化掉，灯不闪了。

**学生反应**：「原来闪烁不是我写对了，是延时刚好够长。」——这句话是本节唯一由他自己得出的结论。

| 为什么 PC13 是低电平亮？我以为是高电平 | 看原理图：3.3V → 电阻 → LED → PC13，PC13 拉低才构成回路 | ✅ 他照着原理图复述了一遍 |

## ✍️ 练习题与作答

| 题号 | 题干 | 他的答案 | 正确答案 | 判定 |
|---|---|---|---|---|
| 1 | 预测：`GPIOC_CRH=0x00200000; GPIOC_ODR \|= (1<<13);` 之后 PC13 是什么电平、灯亮不亮 | 「高电平，灯灭」 | 高电平，灯灭 | ✅ |
| 2 | 诊断：编译过、下载过、灯不亮。最先查哪三处？ | 「灯坏了 / 杜邦线松了 / 程序没下载进去」 | ① IOPCEN 使能没有　② CRH 的 [23:20] 是不是真的配了 PC13　③ 原理图上那根线接的是不是 PC13 | ❌ |
| 3 | 预测：把 PC13 配成开漏（CNF=01）再 ODR 置 1，灯会怎样 | 「亮」 | 不亮：开漏的"高"是高阻，没有外部上拉就没有高电平 | ❌ |
| 4 | 动手：用一条语句把 PC13 拉低 | `GPIOC_ODR \|= (1u << 13);` | `GPIOC_ODR &= ~(1u << 13);` 或 `GPIOC_BRR = (1u << 13);` | ❌ |

**结果**：1 / 4

## ❌ 错题与订正

## 📎 遗漏补全（AI 补的，他没提到的）

1. 题 1 答对了电平，但没提 **PC13 属备份域**：datasheet 限 3mA 灌电流、翻转 ≤2MHz。这条决定了他以后不能拿 PC13 驱动继电器或做高速输出，下节课要点出来。
2. 题 2 那三处里，他只把"引脚位"当成配置问题，另两处（时钟、原理图）在他脑子里还不是"可检查的东西"。
3. 实践代码里的 `volatile` 是抄的，他说不出它挡的是编译器优化——这是"改例程"模式的又一次现场（画像薄弱点 1 的实证）。
