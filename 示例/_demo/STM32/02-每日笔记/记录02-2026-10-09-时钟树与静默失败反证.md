## 🔬 实践记录

```c
/* 反证：与记录 1 的代码只差一行 */
int main(void)
{
    /* RCC_APB2ENR |= (1u << 4); */   /* ← 唯一被注释掉的一行 */
    GPIOC_CRH &= ~(0xFu << 20);
    GPIOC_CRH |=  (0x2u << 20);
    for (;;) { GPIOC_ODR ^= (1u << 13); }
}
```

**实际结果**：编译通过、下载成功、灯一动不动、无任何报错。用调试器打开外设窗口读 `GPIOC_CRH`，
**恒为 0x00000000**——写进去的值根本没落地。

```c
/* 同一节课的后半段：用 SysTick 换掉空循环 */
SysTick_Config(72000);                 /* 72MHz / 1000 = 72000 个节拍 → 1ms */
void SysTick_Handler(void) { GPIOC_ODR ^= (1u << 13); }
```

**学生反应**：「读回来是 0……那就是它压根没收到，不是它收到了但没执行。」——这句是他自己推出来的。

## ❌ 错题与订正

| 题号 | 他的答案 | 正确答案 | 错因 |
|---|---|---|---|
| 3 | 72000 | 71999（或 `SysTick_Config(72000)` 由库替你减） | 把"数到 LOAD 就归零"当成"数了 LOAD 次"。实际是 LOAD+1 次。**这个错在 1ms 上只差 0.0014%，波形上看不出来**，所以永远不会被现象纠正，只能靠概念 |

## 📎 遗漏补全（AI 补的，他没提到的）

1. 题 3 他改对答案后会算，但没意识到这类错误的特征：**误差小到示波器看不出来**。以后配 PWM 分频、串口波特率都是同一类坑（波特率误差 >3% 会开始丢字节）。
2. 题 2 答对了 72MHz，但没提 SystemInit 在 startup 里已经被调用过一次。"默认就是 72MHz"和他"默认 8MHz"的直觉相反，这条要在大点 1 用定时器时再验一次。
3. 反证实验他只读了 CRH，没读 RCC_APB2ENR 本身——"证明自己开了门"和"证明门开了之后有用"是两件事。
