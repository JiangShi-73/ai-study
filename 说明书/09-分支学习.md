# 分支学习：主规划 + 子工作区

> 学到某个大点时，你可能想**另开一个对话、另建一个文件夹**专门啃它。
> 比如主档案是「FPGA 学习路线」，大点 2 是 Verilog —— 你开了个 `HDL学习/` 在里面学。

---

## 一、两个档案各管什么

```
~/学习档案/FPGA/         ← 父：总体规划
    大点 1、2、3……
             └── 大点 2 · Verilog
                     ↓
~/学习档案/HDL学习/      ← 子：这一块的深挖
```

| | 父档案 | 子档案 |
|---|---|---|
| 管什么 | **到哪了** | **怎么学** |
| 谁写 | 主对话 | 子对话 |

**父管进度，子管内容。** 子档案不是父档案的副本。

---

## 二、怎么建

在子对话里说：

> 「这是我子对话的工作区，父档案在 ~/学习档案/FPGA，对应大点 2」

它会跑一条命令把两边关联起来：

```bash
python <技能目录>/scripts/study.py link ~/学习档案/HDL学习 \
    --parent ~/学习档案/FPGA --big "大点 2"
```

之后子档案的契约里会多两行：**上级档案**、**所属大点**；
父档案那个大点下面会多一行「🔗 分支档案：…」。

---

## 三、怎么同步

你在子对话学了几节课之后，回主对话说：

> 「同步一下 HDL 的进度」

它会把子档案的进度汇总进父档案：

| 子档案 | 父档案 |
|---|---|
| 完成标准打勾 2/3 | 大点 2 的状态从 ⬜ 变成 🔄 |
| 上了 3 节课，最后 10-28 | 00 档案的「🌿 分支动态」加一行 |
| 暴露的薄弱点 | 同一行的「结论」栏 |

**只有主对话能改父档案。** 子对话只负责把自己的档案写清楚。

---

## 四、子档案能看到父档案的什么

三样，只读：

1. 父档案里对应的大点（学什么、怎么算学会）
2. 知识库里相关的教材章节
3. 父档案的画像（你会什么、怕什么）

**不会读**父档案的每日记录——那是另一条线的历史，读了只会把上下文撑爆。

---

## 五、什么时候值得分支

| 值得 | 不值得 |
|---|---|
| 一个大点要连着学很多天，内容独立成体系 | 就一两次课 |
| 需要另一套教材/环境（比如换到 HDL 仿真器） | 用的还是同一本书 |
| 你想在另一个对话里专注这一块 | 只是想换个话题聊两句 |

**分支不是免费的**：多一个档案就多一处要维护。

---

## 六、把分支真正并回来

前面说的「同步」只是**汇报进度**——子档案里的记录还在子档案里。
学完之后要把内容**真正搬回主档案**，用 merge：

```bash
python <技能目录>/scripts/study.py merge ~/学习档案/HDL学习 --dry-run  # 先看
python <技能目录>/scripts/study.py merge ~/学习档案/HDL学习            # 真合并
```

| 项目 | 合并后 |
|---|---|
| 每日记录 | 编号接着主档案往下排，每条标注「并入自分支」 |
| 板块笔记 | 同名不覆盖，追加成独立小节 |
| 错题本 | 编号接着排 |
| 知识库 | 去重追加 |
| 画像 | 用子档案的（更贴近最近的学习） |

合并后子档案会被标记「已并入」，**不要再往里写**——继续学在主档案里。

## 七、学完怎么办

1. 子档案自己归档
2. 主对话同步一次，父档案的大点标 ✅
3. 父档案写完成总结，**子档案保留不动**，当详细档案留着

之后主规划继续往下走，子档案变成可查阅的历史。
