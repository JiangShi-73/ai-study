# ai-study 设计说明

## 1. 这个技能解决什么

AI 能回答任何问题，但**回答不等于学会**。市面上的"学习技能"大多停在两件事：出题、讲解。
真正把人从「看得懂」推到「做得出、答得对、记得住」的，是**循环**，不是单次问答。

本技能钉死三件事：
1. **开门先定位** —— 不问清「学什么、现在第几层」，后面全是空转。
2. **日历活着，但服从考核** —— 日历存在且双方都能改，权重随学生清晰度浮动；日期到了考核没过，改日历，不跳步。
3. **笔记分轨** —— 路径（主题轴）、每日（时间轴）、板块（知识轴）各自独立，缺一条就断链。

## 2. 三段式主线

```
定位 intake ──→ 规划 roadmap ──→ 日课 daily ──┐
   ↑                                           │
   └──────── 滚动复习 review ←── 三轨笔记 notes ←┘
```

| 阶段 | 产出 | 判定"这段结束了吗" |
|---|---|---|
| 定位 | 学习契约 + 学生画像 v1 | 六个字段都有值，且水平基线是**考**出来的不是自评 |
| 规划 | 资源锚点 + 大点表 + 完成标准 + 日历 | 每个大点都有 3–5 条能勾的完成标准，且每个大点都能指到锚点资源的某一节 |
| 日课 | 一条每日记录 | 循环走完且归档不空 |
| 复习 | 板块笔记状态更新 | 学生自己挑的条目被讲过一遍 |

## 3. 档案结构：为什么分这么多文件

```
<学习目录>/
  从这里开始.md     给任何 AI 的入口（跨对话继承）
  00-学习档案.md    契约 / 画像（git 式版本）/ 状态看板 / 记录索引   每次开课必读
  01-学习路径.md    大点总览 / 各大点详解 / 完成标准 / 取舍笔记      要学什么、怎么算学会
  02-每日笔记/      记录NN-YYYY-MM-DD-标题.md                     每天的题目 + 笔记，只追加
  03-板块笔记/      内存与指针.md 等                               按板块归并，复习单位
  assets/          截图、代码片段
```

**为什么不合成一个文件**：三条轴的写入规则是互斥的。

| 轴 | 内容 | 改写规则 |
|---|---|---|
| 路径 | 大点 / 完成标准 | 可以改（越改越准），但改完要留痕 |
| 每日 | 某天发生了什么 | **只追加，一个字都不改**（历史是证据） |
| 板块 | 某个知识点现在怎么理解 | **反复重写**（理解变了就要更新） |

把它们塞进同一个文件，必然出现"改 A 的时候顺手美化了 B"。用户原文档已经 1253 行，
其中 250 行是历史记录、60 行是协议、其余是大纲——继续长的结果就是没人读得完。

**分文件的代价**：丢掉"一个文件就能接手"这条优点。
**补偿**：00-学习档案.md 里维护一张**记录索引**（编号 / 日期 / 标题 / 结果 / 文件），
任何 AI 读完 00 + 索引的最后 3 行，就知道上次学到哪、错在哪。

## 4. 三种笔记入口

| | 📌 学生笔记（用户主动） | 📎 遗漏补全（系统自动） | 🧠 板块笔记（双写） |
|---|---|---|---|
| 触发 | 学生说「记一下 / 这个有用 / 存一下」 | 归档时 AI 自查 | 判据命中，或学生说了「记一下」 |
| 时机 | **立刻**进"本轮待归档缓存"，回复里列出来 | 一轮循环结束时 | 归档时同步 |
| 措辞 | **一个字都不改**，原样进引号 | AI 自己的话，标注"他没提到的" | AI 整理，但要保留学生的说法作对照 |
| 落在哪 | 当日记录的 📌 区 | 当日记录的 📎 区 | 03-板块笔记/ |

原文档里前两种**只写进当日记录**，板块笔记没有任何写入路径——附录 D 四个小节至今全是「待填」，
就是这个断链的结果。

**双写判据（三条问，任一条成立就写板块笔记）**：
1. 离开这道题仍然成立吗？（是规律，还是这一步的算式）
2. 下次遇到会想不起来吗？（易错点 / 反直觉结论 / 命令口吻）
3. 学生说过「记一下」吗？（说了就一律双写，不再判断）

**不写**：题目细节、当次环境输出、一次性报错。

## 5. 滚动复习：四层主动权

原文档有「错题重考」但没有「跨课复习」。补上之后最容易犯的错是 AI 每天推一张
"你今天该复习 12 条"的清单——这种设计必然被无视，因为它和学生的节奏打架，而且清单一长人就直接关掉。

所以四层全部交还给学生，**学生说「随便 / 你定」才由 AI 判断**：

| 层 | 学生定 | 学生说「随便」时 AI 怎么办 |
|---|---|---|
| 什么时候开始 | 学生说「复习」才启动，AI 不主动推、不催 | 不存在"AI 主动发起"，这一层无法代劳 |
| 复习哪几条 | 学生挑，或按主题/数量圈定 | 最久没复习 × 掌握度最低，跨板块铺开，上限 5 条 |
| 展示还是提问 | 学生当场定 | 默认**展示**（讲一遍），讲完再问"要考一下吗" |
| 复习几条 / 多久 | 学生定量 | 默认 3–5 条 |

**AI 询问时要顺带给建议**，但只给一次、不纠缠：

> 「可复习的有 8 条。最久没碰的是『按 sizeof 缩放』和『声明与定义』，都停在 🟡。
> 　要复习哪几条？还是我按 3 条给你挑？」

**默认展示式**是这套设计的关键差异：复习的第一动作是**讲给你听**，不是考你。考试是可选的后继动作。

## 6. 苏格拉底引擎：为什么不直接用 socrates-skill

RoundTable02 的 socrates-skill 很干净，但它的核心规则是「**绝不直接给答案**，即使用户哀求」，
并把「几次失败后就给答案」明令列为反模式。

这在真实使用中会进入另一种失败模式：

- 学生反复答不上来 → 技能不允许收口 → **提问循环**，讲不下去
- 学生说「直接告诉我」→ 技能必须硬顶 → 学生关掉对话
- 与「讲清→练习→考核」的教学法冲突：教学需要**先讲**，而它禁止讲

本技能自己写一份，做三处改动：

1. **分档而非一刀切**：`off / soft / hard`，默认 `soft`，学生随时可切，档位记在看板上。
2. **补充出口**：连续无进展、学生明确要求、情绪信号 → **必须**脱离循环给具体提示，再不行给完整答案。
3. **把「绝不放弃」改成「有配额的必然出口」** —— 这正是用户指出的那个坑。

## 7. 与用户现有文档的关系

用户已有一份 1253 行的`FPGA-Linux-ARM-x86-学习路线.md`，它同时是**协议**（第一、二部分）
和**实例**（第三、四部分的 FPGA 大纲与真实记录）。

本技能只抽取**协议**并泛化，不复制那份大纲。已有档案走「接手」路径：
触发「接手我的学习档案」→ daily.md §7 接手清单，**不重建、不覆盖、不改历史**。
迁移时它按 00/01/02/03 拆分，内容原样搬，不重写（见 files.md 的迁移条款）。

## 8. 日历与决策权重（已裁决）

早期版本按原文档口径"不排日历"，与用户「要说明多久学完」的要求冲突。用户裁决为：

- **日历可以有，而且必须是活的。** 学生和 AI 都有改动权限。
- **日历服从考核**：日期到了但考核没过 → 改日历，不跳步。日历是承诺，不是命令。
- **权重随学生清晰度浮动**：学生清楚 → 学生主导；说得清用途说不清路径 → 共同；基本不清楚能学什么 → **AI 主导**。

第三行是这个模型里最有价值的一条：**学生越不清楚，AI 越要担责，而不是退让。**
甩三个选项给一个不知道自己要什么的人，等于把选择成本又推回去。

权重与苏格拉底档位一样，存进 `00-学习档案.md` 的看板，访谈时定，随时可改。
学生说「随便 / 你定」= 临时进入 AI 主导，只对这一次生效。

## 9. 资源锚点

用户指出：路径规划应当推荐参考教材与大学公开课，依托它们生成大纲——「经典永不过时」。

这条改变了大纲的生成方式：**先选锚点，再从锚点反推**，而不是让模型凭空写大点。
锚点三件套（主教材 / 视频课 / 练习源）缺一不可，各自承担结构、节奏、反馈。

凭空生成的大纲有个通病：看起来专业，学到第二章就断，因为你没有习题梯度作为校验。
经典教材的目录 + 名校 course syllabus 已经被几十年、几十万人用过了，那才是免费的验证。
详见 roadmap.md §2–3。

## 10. 2026-10-22 验收事故与修复

第一次实战验收时，执行代理被要求「把 STM32 放进 示例/」，结果**伪造了 4 节课、1 次复习、902 行档案**，
而 `study.py lint` 全绿。事故报告见 `示例/ai-study-验收报告-2026-10-22.md`。

根因不是执行者不听话，是技能的三处结构性缺陷：

| 根因 | 修复 |
|---|---|
| **没有演示通道** —— 想看产出长什么样，唯一的路就是编一份像样的 | `study.py demo-init` + `示例/_demo/` 物理隔离 + `demo: true` front-matter + 专门路由 |
| **lint 不查真实性** —— 只查待填/编号/元数据/索引，编的档案长得一样 | 记录头加 `类型` / `真实性`；**用文件创建时间（ctime）反推**：声称某天上了课，但文件是今天建的 → 报错。预支复习同理 |
| **基线不可追溯** —— 「水平是考出来的」写在散文里，没有落点 | `templates/记录00-YYYY-MM-DD-定位访谈.md` + 契约「基线来源」字段 + lint 要求有基线必须有记录00 |

**最有用的那一条是 ctime 反推。** 日期可以随便写，但文件什么时候被创建是操作系统记的，编不了。
这一条把「倒填历史」从"靠自觉"变成了"机器可查"——修复前 902 行全绿，修复后同一批文件报 19 条错。

## 11. 知识库（2026-10-23 增补）

第一轮实测暴露两件事：**资料没地方放**，以及**路径生成后没给用户看**。

### 11.1 知识库：存清单和用法，不存原文

对标 DeepTutor 那种"上传课件建知识库"的做法，我们刻意反着走：

| | 它们的知识库 | 我们的知识库 |
|---|---|---|
| 存什么 | 教材/论文原文，做向量检索 | 资料清单 + 用法，原文留在用户手上 |
| 目的 | 检索相关内容喂给模型 | 让每条大点的「学什么」能指到具体章节 |
| 风险 | 版权、体积、检索到 ≠ 学会 | 无 |

**为什么不做 RAG**：检索到 ≠ 学会。知识库在这里的作用不是"给模型喂料"，是**让人知道该翻哪一页**。

### 11.2 三处告知 / 落库的时机

1. 定位访谈第 5 轮：**告知**（「你手边的书我会登记进知识库」）
2. 路径规划完成：**锚点落库**并为每条大点的「学什么」提供出处
3. 学生随时给新资料：**登记**，并回一句编号

处理（把 ⬜ 变 ✅）= 一句话摘要 + 章节到大点的映射 + 三种场景的用法 + 缺口标注。
锚点资料不处理，大点的「学什么」就写不出来——这条已进 lint 警告。

### 11.3 路径必须展示（修一个真 bug）

原 roadmap §8 写的是"只告诉学生第一个大点"，实际执行变成了"只写文件不吭声"。
学生看不到路径，就不知道存不存在、对不对、要不要改。

现在的规则是**三样摆出来 + 三问确认**：大点总览表 / 知识库清单 / 第一个大点细节，然后一次问完顺序、范围、时间。
把"落盘"和"告知"拆成了两步，缺一步算没做完。

## 12. 外包给子代理（2026-10-23）

真实运行形态是「便宜的主对话 + 贵的主模型子代理」，而技能原来默认一个 agent 从头执行到底，
于是主模型要么硬扛做不好，要么偷偷开子代理、没人管交接和回收。

### 12.1 核心判断：不假设环境

不同 agent 的子代理能力分五类：每次调用可选（DSH）、专家各自绑定（WorkBuddy）、
会话/专家级（Qoder）、配置级（Codex CLI）、定义时写死（Claude Code），还有根本没有的。
**先探测再决定**，编码时不许编模型名——编了会被拒或悄悄回退，两种情况都会让你误以为用了强模型。

### 12.2 模型选择：四层兜底

学生指定 → 问一次（带建议）→ 学生说「随便」就自己挑并说明理由 → 挑不出来用环境默认。
**宿主规程 > 技能默认**：某些环境规定开子代理前必须先问、强度按固定值，那就照它的来。

### 12.3 外包什么：看「错一次会不会污染档案」

判题、定路径、出题值得花钱；讲授、答疑、闲聊不值得。

### 12.4 交接包决定八成成败

子代理看不到主对话。必带六样（画像快照 / 当前大点与完成标准 / 上次课三行 /
任务与验收标准 / 硬约束 / 输出格式模板）。少给一条，它就会给出一个前提错误的专业答案。

### 12.5 子代理不许直接写档案

只交回内容，主模型核对后落盘，并在记录里标注来源。
**核对的活不能外包——外包方核对自己的产出，等于没有核对。**

### 12.6 触发条件（已定）

用户给的五条，全部关于**上下文预算与结构完整**，与「难不难」无关：

1. 上下文占用大（整章讲义 / 一套卷子 / 大点验收复盘）
2. 学生一直弄不懂（连续 2 次 🔴 / 追问超 3 轮 / 要出 5 道以上题）
3. 学生要求
4. 学生插嘴问跑题的（塞不进大纲）
5. 会破坏结构的内容（要长篇、打乱节奏、与当前大点无关）

这个模型比我最初提的「错一次会不会污染档案」更可靠：**便宜模型判断不准难度，
但判断得准「这东西占地方」**。校准差的能力不能拿来做触发器。

与之配套的两个反转：
- **外包负责生成，不是只做判断** —— 占上下文的就是生成
- **草稿文件允许，档案落盘禁止** —— 子代理写 `_drafts/`，主模型抽查后移入

4、5 类跑题内容默认不进档案，否则会把大纲结构拆松。

## 13. 三模式架构（2026-10-23）

用户要把技能扩成三种模式：教师（已实现）、伴学、考前突击。

### 13.1 核心判断：共用的一半比不同的那一半大

档案结构、真实性闸门、知识库、复习、配图、外包、苏格拉底引擎——这七份任何模式都改不了一行。
真正变的只有「一节课怎么走」。

所以**没有搬任何现有文档**（搬一次会打断几十处交叉引用），只加一层模式定义：
`references/modes/README.md` 说清共用什么、每个模式必须回答哪四格；具体模式放 `modes/*.md`。

**新增模式的门槛被压到四格**：谁主导 / 一节课怎么走 / 产出什么 / 什么时候算结束。

### 13.2 一个计划一个模式

模式写在契约里，不是全局开关。平时教师、考前突击，是正常用法，切换要留痕。

### 13.3 不给学生出选择题

「你要哪个模式」是设计者视角。学生只会说「陪我学」「下周考试」。
所以 SKILL.md 里写的是**听诉求判断**，拿不准才问一句人话。
