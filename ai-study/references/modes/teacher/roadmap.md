# 路径规划（roadmap）

**什么时候用**：学习契约已落定（intake 完成），还没有 `01-学习路径.md`；或学生说「给我规划一下」「我该按什么顺序学」。

**产出**：`01-学习路径.md` —— 资源锚点 + 大点表 + 完成标准 + 日历。

---

## 1. 一个大点是什么

大点 = **一个能独立验收的能力块**，而不是一章书、一个工具、一个知识点。

判别标准：完成后能对别人说出「我现在会 X 了」，而且这个 X 能被观测到。

- ✅ 「能用 gdb 定位空指针崩溃的**具体行**」
- ❌ 「学会 gdb」

**数量**：4–8 个。少于 4 个说明切太粗（验收周期太长，学生中途看不到进展）；多于 8 个说明切太碎（永远在第一章）。

**大点之间串行。** 只有当前大点全部达标才解锁下一个——同时开两条线的结果一定是两条都停在第三章。

---

## 2. 先选锚：教材 + 课程 + 练习源

**不要凭空写大纲。** 凭空写出来的大点，本质是 LLM 的幻觉，看起来很像回事，实际经不起一遍学。

正确的做法是**先找经典，再从经典反推大纲**——经典被几十年、几十万人打磨过，它的目录结构和习题梯度本身就是一份验证过的学习路径。

### 2.1 锚点三件套

| 角色 | 作用 | 例 |
|---|---|---|
| **主教材** | 结构性：章节顺序、定义准确、有习题可出题 | CSAPP 3rd / K&R / 模电第六版 |
| **视频课** | 节奏性：有人替你讲一遍，卡住时换视角 | MIT 6.004 / 中国大学MOOC / B 站系统课 |
| **练习源** | 反馈性：大量可判对错的小题 | HDLBits / 教材习题 / LeetCode / 课程实验 |

**三件缺一不可**：只有教材 → 容易卡住没人讲；只有视频 → 学完不会写；没有练习 → 无法验收。

### 2.5 锚点必须落进知识库

选完不是停在对话里，要**登记进 `04-知识库/索引.md`**，角色标「锚点」，然后按
[knowledge-base.md](../../core/knowledge-base.md) §5 处理到 ✅。

**锚点不处理，大点的「学什么」就写不出来。** 三条锚点是这个规则的最小集。

### 2.2 选教材的三条硬标准

1. **在版且被广泛采用**——多版本、多校在用、有公认的译名（不是某个人的讲义）
2. **有习题且答案可得**——没有习题的教材用来出题会瞎编；答案拿不到就没法判分
3. **目录粒度清晰**——章 / 节能对应到一次课，不是"第一部分：思想"这种

### 2.3 视频课从哪找

- **MIT OCW / edX / Coursera**：有完整 syllabus + 作业 + 视频，最接近"大学课"
- **中国大学 MOOC**：中文、配套教材、有作业
- **B 站系统课**：中文易得，但要挑**有完整章节**的系列，不挑碎片讲解
- 判断标准不是"讲得好不好听"，而是**有没有作业和可验收的产出**

### 2.4 必须查可得性

推荐之前先确认：这门课还开着吗？教材学生买得到吗？视频有中文字幕吗？练习站要不要付费？
**推荐一个学生拿不到的资源，等于没推荐。**

## 3. 从锚点反推大纲

拿到教材目录 + 课程 syllabus 之后，按四步合成：

| 步 | 做什么 |
|---|---|
| 1 | **对齐**：把教材章节和课程讲次摆在一起，逐条比对 |
| 2 | **交集 = 必学核心**：两边都有的，基本跑不掉 |
| 3 | **差集 = 取舍点**：教材有课没有（可能过时或超纲）；课有教材没有（补充材料）——每一条都要写进"关键取舍"并写理由 |
| 4 | **转标准**：每条核心 → 一条可判定的完成标准（§4）；再把标准分组成 4–8 个大点 |

**产出必须先给学生看资源清单**，不是直接甩大纲：

| 资源 | 类型 | 用途 | 为什么选它 | 学生拿得到吗 |
|---|---|---|---|---|
| CSAPP 3rd | 主教材 | 结构性 | 计算机系统的公认标准教材，习题梯度好 | 有 PDF |
| MIT 6.004 | 视频课 | 硬件视角 | syllabus 完整、有作业 | OCW 免费 |
| HDLBits | 练习源 | 可判对错 | 在线判题，反馈即时 | 免费 |

**五选三原则**：不要一口气列十个资源。主教材一个、视频课一个、练习源一个，先把这一组跑通。

---

## 4. 完成标准怎么写

标准是**动词 + 可观测 + 规模**，三样缺一不可。

| | 例 |
|---|---|
| ✅ | 不看资料手写单链表的插入/删除，并在空表、头插、尾删三个用例上跑通 |
| ✅ | 给定一段崩溃的 C 代码，5 分钟内用 gdb 说出崩在哪一行、哪个变量、什么信号 |
| ❌ | 掌握链表 |
| ❌ | 理解指针 |
| ❌ | 熟悉 gdb |

**三条检查**：
1. 能不能**当场验证**？（跑出来 / 说出来 / 写出来）
2. 能不能**判失败**？判不了的（"理解了"）不是标准。
3. 学生能不能**自己判断完成没完成**？（他判不出来，说明标准太模糊）

每个大点 **3–5 条**，全部打勾才算完成。

---

## 5. 顺序怎么定

四条排序原则，从上往下优先：

1. **依赖优先**：后面要用到前面的，就必须在前。
2. **能立刻动手的优先**：抽象理论先搭一个最小可运行例子，摆在前面比在后面当背景好。
3. **能形成正反馈的优先**：第一个大点要能在 2–3 次课内出结果。第一个大点就是弃学高发区。
4. **能贯穿全线的优先**：选一个工具（gdb / git / 调试器 / 笔记系统）早点学会，后面全程受用。

**锚点资源自带的顺序优先于你的偏好。** 教材先讲什么、课先讲什么，通常有它的道理；
你要改，就在「关键取舍」里写清为什么改。

## 6. 时长与日历

**日历是可以有的，而且必须是活的。**

### 6.1 三条规则

1. **日历服从考核，不是反过来。** 日期到了但考核没过 → **不跳过，改日历**。日历是承诺，不是命令。
2. **学生和 AI 都有改日历的权限。** 谁发现不匹配谁提出来；改之前说清"改什么、为什么、改了什么不变"。
3. **权重随学生的清晰度浮动。** 见 §6.3。

### 6.2 什么时候必须提出改日历

命中任意一条，就要**主动**提，不要等到崩了才说：

- 连续两次课考核 < 60%
- 实际进度与计划位置相差 ≥ 1 次课
- 学生自己说「跟不上了 / 太慢了 / 太简单了」
- 大点的完成标准明显定错了（太高或太低）
- 学生的资源变了（书换了、课停了、每周时间减半）

提出时的格式：**事实 + 原因 + 改法 + 什么不变**

> 「计划是 11-05 完成大点 1，实际还差 2 条完成标准，而且指针缩放这一条已经卡了两次课。
> 　建议把大点 1 的目标日挪到 11-12，完成标准不降。这样改行吗？」

### 6.3 决策权重

| 学生的状态 | 权重 | AI 的具体做法 |
|---|---|---|
| 清楚要学什么、有明确的资源偏好 | **学生主导** | 只给建议，学生不点头不改 |
| 说得清用途，说不清该怎么走 | **共同** | 给 2–3 个方案对比（差别在哪、代价是什么），学生选 |
| 基本不清楚自己能学什么 | **AI 主导** | 直接给**一个**明确方案 + 理由，学生只需点头或否决 |

**"不清楚"是最需要 AI 担责的时候，不是最该退让的时候。** 给三个选项等于把选择成本又推回去。

权重存在 `00-学习档案.md` 看板的「决策权重」一行，访谈时定，随时可改。
学生说「随便 / 你定」= 当场临时进入 AI 主导，只对这一次生效，不改看板。

### 6.4 日历写到什么粒度

- **默认粒度：大点**。写「大点 1 目标 2026-11-05」这种目标日期。
- 学生要求更细 → 细到周，不细到天。细到天必然崩，崩了就没人信这个日历了。
- **永远用真实日期 + 第 N 次课**，不要用「Day 1」「第 3 周」当学习单位。

### 6.5 学生要一个"大概多久"

正常回答就行，但必须带上不确定度：

> 「按每周 3 次、每次 2 小时估，大点 0 到约 2–4 周。
> 　这个估算是拿现在的时间投入算的，你时间一变它就得改——所以它写在日历里，不是合同。」

## 7. 每个大点必须写四块

| 块 | 要求 |
|---|---|
| **学什么** | 落到具体位置：书名 + 版次 + 章 + 节 + 页；或课程 + 第几讲。不许写"了解一下 X" |
| **动手做什么** | 能在学生自己环境里跑起来的完整命令 / 完整代码 / 预期现象。不许让他先去配环境 |
| **怎么算学会** | §4 的完成标准，3–5 条，可勾 |
| **解锁条件** | 默认 = 上述标准全打勾；若允许部分解锁，要写明是哪几条 |

另外留三格**后面填**：

- **目标日期**（日历，可改）
- **📝 完成总结**（全打勾后写：真正获得了什么、踩过最大的坑、遗留薄弱点）
- **⏳ 遗留**（没学透但先过的地方，回头要补）

---

## 8. 产出后：必须展示，不能只落盘

> **只写文件不说，等于没做。** 学生看不到的东西，他不知道存不存在、对不对、要不要改。
> 这是第一轮实测暴露的真实缺陷——路径生成了，学生一眼都没看着。

### 8.1 先把三样摆到对话里

1. **大点总览表**（全部 4–8 个，一行一个）：

   | 大点 | 核心目标（一句话） | 完成标准 | 目标日期 |
   |---|---|---|---|

2. **大点依赖图**（Mermaid，一次一张）：哪些串行、哪些有前置、哪条是主线
   —— 见 [visuals.md](../../core/visuals.md) §4。学生确认结构后再渲染成图存 `assets/`

3. **知识库清单**（3–8 条）：编号 / 名称 / 类型 / 它干什么用
4. **第一个大点的细节**：学什么（哪本书哪一节）/ 动手做什么 / 3–5 条完成标准

### 8.2 然后问三个确认（一次问完，别逐条追问）

- **顺序**对不对？（有没有前置没打底、有没有该先学的排后面了）
- **范围**对不对？（有没有不该进来的、该进来的没进来）
- **时间**对不对？（跟你每周投入匹配吗，还是明显赶/松）

### 8.3 最后收口

- 学生确认 → 更新看板，问一句「今天从大点 0 开始，还是先热身？」
- 学生要改 → 改 01 并留痕，**改完再展示一次**（不要默默改完就开讲）

### 8.4 不要做的

- ❌ 只发一句「学习路径已生成到 01-学习路径.md」——这不是展示，是通知
- ❌ 把 8 个大点的详解全铺出来——那是文件里的内容，用户要看自己翻
- ❌ 展示完不问确认就开讲第一节

## 9. 反模式

- ❌ **不选锚点直接写大纲**（幻觉大纲，学两章就断）
- ❌ 只给教材不给课（卡住没人讲）、只给课不给练习（学完不会写）
- ❌ 推荐学生拿不到的资源（付费墙、已下线、无中文字幕）
- ❌ 一口气列十个资源让学生自己挑
- ❌ 大点按书目录硬切（书目录是作者的叙事顺序，不是能力顺序）
- ❌ 完成标准写"理解 / 熟练 / 了解"
- ❌ 一次讲完整条路径（学生会以为在学习，其实在看目录）
- ❌ 日历写死到天（必然崩，崩了就没人信）
- ❌ 考核没通过却按日历往下走
- ❌ 学生说不清楚要什么，你还甩三个选项过去
- ❌ 大点数量超过 8（说明你在写书，不是在规划）
