# 三种模式

> 同一个内核，三种带法。**共用的一半比不同的那一半大得多**——
> 档案结构、真实性闸门、知识库、复习、配图、外包，这些不分模式。
> 真正变的只有一件事：**一节课怎么走。**

---

## 1. 模式一览

| 模式 | 一句话 | 学生什么时候要它 | 状态 |
|---|---|---|---|
| **教师** | AI 主责：讲 → 练 → 考 → 评 → 归档 | 「教我这个」「带我学」 | ✅ 已实现 |
| **伴学** | 学生带材料来，AI 答疑并沉淀成错题 + 知识点 | 「这题怎么做」「帮我看看这份作业」 | ✅ 已实现 |
| **突击** | 只做解析与整理：题目 → 三份考点文档 | 「下周三考试」「突击一下」 | ✅ 已实现 |

## 3. 每个模式必须定义的四件事

新增一个模式，只填这四格：

| # | 必须回答 | 教师模式的答案（示例） |
|---|---|---|
| 1 | **谁主导** | AI 讲，学生练 |
| 2 | **一节课怎么走** | 十步循环（daily.md） |
| 3 | **产出什么** | 一条每日记录 + 板块笔记 + 画像核对 |
| 4 | **什么时候算这一课结束** | 归档完成 |

## 4. 模式记在哪

**一个计划一个模式**，写在 `00-学习档案.md` 的契约里：

```
| 模式 | 教师 |
```

合法值：`教师` / `伴学` / `突击`（可带括号说明，如 `突击（6 月 20 日期末）`）。

**切换模式要留痕**：改契约 + 在看板「最近一次改日历」旁记一行，说明为什么切。
平时用教师模式、考前切突击，是正常用法，不是失败。

## 5. 怎么选模式

**第一轮必须问，问完不再问。** 三个词学生可能不认识，所以问的时候要带人话解释
（SKILL.md「第 0 步」里有现成的话术和表格，直接照说）。

三条判断：

| 情况 | 怎么做 |
|---|---|
| 他第一句已经指明（「陪我学」「下周考试」「教教我」） | 别再问一遍，确认一句就开工 |
| 能猜但不确定 | 带默认地问：「我按教师模式来，行吗？」 |
| 他说「随便 / 你定」 | 按处境判断，并说明为什么这么选 |

**为什么值得单独问一次**：三个模式的档案结构和一节课的走法都不一样，
选错之后所有记录都得重来。这是少数几个**问清楚比省一轮更划算**的地方。

## 6. 新增模式的步骤

1. 在 `modes/` 下建 `<模式名>.md`，只填 §3 那四格
2. 在 §1 的表里加一行
3. 契约「模式」的合法值加一项
4. 在 `scripts/study.py` 的 `MODES` 里加一项（否则 lint 会报非法）
5. 加一条回归测试

**不许做的**：为了新模式去改内核那七份文档；或在 SKILL.md 里堆模式细节
（SKILL.md 只放路由，细节进 modes/）。

## 7. 开放问题（等定义时拍板）

### 伴学

**已定义**，见 [companion.md](companion.md)。仍悬着的：

- 学生一次发一整份试卷（十几道），是逐题过还是只挑典型？现在默认「先问他要哪几道」
- 错题本的复习要不要和板块笔记分开排？（现在统一走 review，靠板块笔记取货）

### 突击

**已定义**，见 [cram.md](cram.md)。仍悬着的：

- 多份真题混在一起统计时，要不要按年份分开看？（现在默认合并，来源记在每条错题上）
- 分值统计要不要支持"按题型"（选择/填空/大题分别占比）？现在只按章节和考点


### 跨模式

- 一个计划中途切模式，历史记录怎么处理？（建议：不处理，记录上是「第 N 次课」，模式记在当时的契约里——但契约会变，历史就读不出来了）
