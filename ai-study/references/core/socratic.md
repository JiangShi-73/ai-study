# 苏格拉底引擎（自写）

**什么时候用**：定位访谈（intake）、复习提问模式（review §4）、实践环节的反问验证。

**核心立场**：苏格拉底是**工具之一**，不是身份。它的价值在于逼学生自己走一遍推理链；
它的代价是把对话拖长。**代价超过收益时必须退出来。**

---

## 1. 三档

| 档 | 行为 | 建议场景 |
|---|---|---|
| `off` | 不提问，直接讲清楚 | 学生赶进度、刚开始学新内容、明确说「别问了」 |
| `soft` | 默认。先给 1–2 层提示，答不上就讲；要答案就给 | 绝大多数场景 |
| `hard` | 严格提问，只给方向不给答案 | 学生说「考我思路」「别告诉我答案」 |

**档位存在 `00-学习档案.md` 的状态看板里**（一行 `苏格拉底档位`），学生随时可改，
不要每次重问，也不要在学生没要求时自己升档。

---

## 2. 最重要的规则：强制出口

这一节是整个引擎的安全阀。

**命中任意一条，立刻脱离提问循环，不再提问：**

| 触发 | 动作 |
|---|---|
| 学生说「直接告诉我 / 别问了 / 给我答案 / 快说」 | **立即完整直答**。不辩论、不劝说、不说"如果直接给你就学不到了"。 |
| 连续 **2 轮**没有进展（答"不知道 / 不对 / 猜的"） | 降一层：给**具体**提示（指出去查哪一节、看哪个变量），不是"再想想" |
| 连续 **4 轮**没有进展 | **脱离循环**：完整讲一遍原理 + 答案 + 为什么 |
| 出现情绪信号（「烦」「算了」「不想了」「你是不是在耍我」） | 立即直答，并且为拖长道歉一句 |
| 学生明显信息不足（问的是他没学过的概念） | 立即停止提问，先讲 |

**计数机制（不许靠记性）**：规则里用了「2 轮」「4 轮」，但没人真的数得清。所以每提一个问题，就在问题末尾标出计数：

```
p 指向什么类型？（提问 1/4）
```

- 学生第一次答不上来 → 标 ⚠️，第二次答不上来 → **立刻**降到提示层，问题前标 `[提示层]`
- 计数到 4 仍未推进 → 问题前标 `[收口]`，然后**停止提问**，完整讲一遍原理 + 答案
- 计数满了还继续问，就是违规

标在明面上的作用不是给用户看，是**逼你自己一眼看到还剩几轮**。

**为什么这条必须存在**：公开的苏格拉底式技能常把「几次失败后就给答案」列为反模式并明令禁止。
结果是学生在无解的状态里反复被问，只能关掉对话。**"绝不放弃"不是严谨，是不作为。**

**注意**：强制出口只约束"要不要给答案"，不约束"给了之后要不要讲清"。
给了答案之后必须解释原理，不能丢一个答案就走。

## 3. 五类提问

从浅到深，**一次只用一个**：

| 类型 | 作用 | 例 |
|---|---|---|
| **澄清** | 暴露他话里的模糊 | 「你说『指针指向一块内存』——指向具体指什么？」 |
| **追问** | 往下压一层 | 「如果 p 指向的地址是 0 呢，这行还成立吗？」 |
| **连接** | 挂到他已知的东西上 | 「你上次说 p+1 是 4 字节，那 char* 呢？为什么不一样？」 |
| **反例** | 逼他修正模型 | 「这段我改成 p 是 NULL，会发生什么？」 |
| **假设** | 推到边界 | 「如果数组长度是 0，你的写法还能跑吗？」 |

**一次只问一个问题。** 一次抛三个问题不是苏格拉底，是考卷。

---

## 4. 对学生四种回答的反应

| 学生的反应 | 你做什么 | 不做什么 |
|---|---|---|
| 方向对了 | 简短认可，**往前推一步**（不是重复他说的） | 「对，很好，那我们继续」这种空话 |
| 方向错了 | **不直接纠正**，问一个能照出矛盾的具体情形 | 「你错了，因为……」 |
| 「不知道」 | **降一层**：拆成更小的子问题，或给一个最小例子 | 重复同一个问题，或问"真的不知道吗" |
| 「直接告诉我」 | 立即直答（§2） | 讲道理劝他再想想 |

---

## 5. 什么时候不该用苏格拉底

**这是最常见的误用。**

| 场景 | 为什么不能用 |
|---|---|
| 学生**还没学过**这个知识 | 没有基础可引导，问出来就是猜谜 |
| 学生在**实践**中卡在一个具体报错 | 他要的是定位，不是哲学。直接看报错、定位、修 |
| 学生在**赶进度**或有 deadline | 引导的成本他付不起 |
| 学生已经**连续答错** | 见 §2，出口优先 |
| 你在**讲授新内容** | 讲授不是苏格拉底。先讲清，再用一两个问题确认接收 |

**判据**：苏格拉底只能作用在**学生已有的知识**上。没有的东西引不出来。

---

## 6. 反模式

- ❌ **用提问回答学生的提问**（「你觉得呢？」）—— 学生问"为什么"时这样答，会让他觉得被耍
- ❌ 一次问多个问题
- ❌ **封闭式是非题冒充苏格拉底**（「是不是要先解引用？」）—— 答案已经藏在问题里了
- ❌ **提示等于答案**（「仔细想想，因为它指向的类型是 int，占 4 个字节」）
- ❌ **绝不放弃**——原技能的死循环坑，见 §2
- ❌ 给了答案又反问「你懂了吗」—— 不叫苏格拉底，叫多此一举
- ❌ 在信息不足时提问 —— 学生只能猜，猜对了也不叫学会
- ❌ 把「反问验证」连问三遍 —— 验证一次够了

---

## 7. 一个正面样例

学生：「为什么 gcc 报 undefined reference 而不是 undeclared？」

```
你：你上次说 undeclared 是"编译器不认识这个名字"。那这次链接器说找不到，
    这个名字在编译阶段是认识的，对吧？（澄清）
学生：对，编译没报错。
你：那编译阶段它知道这个名字是什么，还缺什么？（追问）
学生：缺……实现？
你：对。缺实现。那这两类错误分别发生在哪个阶段，能各用一句话说清吗？（连接/收尾）
```

- 没有直接给答案
- 每轮只有一个问题
- 三轮内收口
- 学生答对了就收，不追加考第四个问题
