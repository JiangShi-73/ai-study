# 分支档案：主规划 + 子工作区

> 一个学习计划学到某个大点时，学生可能**另开一个对话、另建一个文件夹**专门啃它。
> 比如主档案是「FPGA 学习路线」，大点 2 是 Verilog —— 他开了个 `HDL学习/` 在里面学。

---

## 1. 两个档案是什么关系

```
~/学习档案/FPGA/         ← 父：总体规划（父档案）
    01-学习路径.md         大点 1、2、3……
             │
             └── 大点 2 · Verilog
                     │
                     ↓ 分支
~/学习档案/HDL学习/      ← 子：这一块的深挖（子档案）
```

| | 父档案 | 子档案 |
|---|---|---|
| 管什么 | **到哪了** | **怎么学** |
| 有什么 | 全部大点、日历、整条路线的画像 | 这一块的大纲、记录、错题、板块笔记 |
| 谁写 | **只有主对话** | 子对话 |
| 频率 | 每次同步时更新一行 | 每次课都写 |

**一句话**：父管进度，子管内容。

## 2. 建立关系：link

在**子档案**里跑（或在主对话里指明父档案）：

```bash
python scripts/study.py link <子档案目录> --parent <父档案目录> --big "大点 2"
```

它做两件事：

1. 子档案契约写入「上级档案」「所属大点」
2. 父档案的大点详解里插入一行 `> 🔗 分支档案：<路径>`

## 3. 同步：sync

```bash
python scripts/study.py sync <子档案目录>
```

把子档案的进度汇总回父档案：

| 读子档案的 | 写父档案的 |
|---|---|
| 当前大点、实际位置 | 大点总览里那一行的状态（⬜ → 🔄 → ✅） |
| 完成标准勾选比例 | 大点详解标题旁的状态 |
| 记录数、最近一次日期 | 00 档案的「🌿 分支动态」表新增一行 |
| 暴露的薄弱点 | 同一行的「结论」栏 |

**谁跑**：主对话跑。子对话只负责把自己的档案写清楚，**不去改父档案**。

## 4. 独立性：子档案不许变成父档案的镜像

| 子档案**要**有的 | 子档案**不要**有的 |
|---|---|
| 自己这一块的大纲和完成标准 | 父档案的全部大点 |
| 自己的每日记录、错题、板块笔记 | 父档案记录的副本 |
| 只跟这一块相关的知识库 | 父档案的完整资料台账 |

**为什么**：子档案是**工作区**，不是备份。复制父档案会让两边都变重，而且一改就要同步两处。

## 5. 子档案能看到父档案的什么

可以读，但只读这三样：

1. **父档案里对应的大点**（学什么、怎么算学会）——这是任务的来源
2. **知识库里相关的锚点**（教材哪几章）——免得重复登记
3. **父档案的画像**（学生会什么、怕什么）——教学风格要对得上

**不要读**父档案的每日记录。那是另一条线的历史，读了只会把上下文撑爆。

## 6. 冲突与边界

| 情况 | 怎么办 |
|---|---|
| 子档案说完成了，父档案的完成标准没勾 | 以**父档案的完成标准**为准；子档案要补勾才 sync |
| 两边画像不一致 | 以**子档案更新**的那个为准（它更贴近最近的学习），sync 时写回父 |
| 父档案改了日历 | 子档案不自动跟随；主对话 sync 时说明差异 |
| 子档案想改父档案的大纲 | **不允许**。子档案只能通过 sync 汇报，改大纲的权力在父 |

## 7. 什么时候该分支

| 该分支 | 不该分支 |
|---|---|
| 某个大点要连着学很多天，内容独立成体系 | 就一两次课的内容 |
| 需要另一套教材/环境（比如换到 HDL 仿真器） | 用的还是同一本书同一条线 |
| 你想在另一个对话里专注这一块 | 只是想换个话题聊两句 |

**分支不是免费的**：多一个档案就多一处要维护。为一个大点分支，值；为一节课分支，不值。

## 9. 合并：把分支真正并回来

`sync` 只是**汇报进度**，子档案的东西还在子档案里。
`merge` 才是**把内容搬过来**——像 git 的分支合并。

| | sync | merge |
|---|---|---|
| 做什么 | 父档案多一行汇报 | 记录、错题、笔记、画像真正搬进父档案 |
| 什么时候 | 随时，可以跑很多次 | 这个分支学完了，跑一次 |
| 之后 | 子档案继续写 | 子档案封存，不许再写 |

```bash
python scripts/study.py merge <子档案目录> --dry-run   # 先看要干什么
python scripts/study.py merge <子档案目录>             # 真合并
```

### 合并规则

| 项目 | 怎么处理 |
|---|---|
| **每日记录** | 父档案编号接着往下排；每条顶部加一行「🔀 并入自分支 X · 原记录 03」 |
| **板块笔记** | 同名不覆盖，子版本追加成独立小节并标注入并来源 |
| **错题本** | Q 编号接着父档案排，原编号作废（文件里还能看到来源） |
| **知识库** | 按名称去重追加 |
| **画像** | 用子档案的（更贴近最近的学习） |
| **大点状态** | 按子档案的完成标准比例更新 ⬜ → 🔄 → ✅ |

### 为什么要重编号

父档案已有「记录01–05」，子档案也有「记录01–03」。直接拷过去就撞号了。
重编号 + 在文件头写明原编号，历史可追、编号不冲突。

### 合并之后

子档案顶部会被加上：

> ✅ 本档案已于 2026-10-30 并入「FPGA」。
> 内容保留作为详细历史，**不要再往里写新东西**——继续学请在父档案里进行。

契约里也会记一行「并入状态」。再跑一次 merge 会被拒绝。

## 8. 收尾

子档案那个大点学完：

1. 子档案自己归档（记录、板块笔记、画像核对）
2. 主对话跑 `study.py sync`，父档案的大点标记 ✅
3. 父档案写「完成总结」，子档案**保留不动**，作为那一块的详细档案

之后父档案继续往下走，子档案变成可查阅的历史。
