# 配图（visuals）

**什么时候用**：路径规划完成时（依赖图）；讲授「空间或时间关系」的概念时；整理板块笔记时。

---

## 1. 判据：只有两种东西该画

**问一句：这个概念是空间关系，还是时间关系？**

| 类型 | 例子 | 画什么 |
|---|---|---|
| **空间** | 内存布局、结构体、指针指向、电路拓扑、寄存器位域、集合包含 | 布局图 / 拓扑图 |
| **时间** | I²C 时序、状态机、中断响应、调用栈生长 | 时序图 / 状态图 |
| **依赖** | 学习路径的大点顺序、算法步骤 | 流程图 / 依赖图 |

**两种都不是 → 不画。** 「什么是耦合」「为什么抽象重要」这类，画出来只会更糊。
图不是让内容显得专业的手段，是**代替一段说不清的文字**。

---

## 2. 一条铁律：错一张毁十句

图是 AI 生成的，**画错就是另一种编造**。渲染出来比文字更有说服力，也就更容易骗人。

画完必须自查三条：

1. **拓扑对**：箭头方向、连接点、层级关系
2. **数值对**：地址、位宽、字节数、时钟频率——**图里每个数字都要能在正文找到出处**
3. **无装饰节点**：每个框、每条箭头都承载信息，去掉就丢东西

> 电路图和时序图尤其危险：它们最像"真的"，也最容易错一个细节就全错。

---

## 3. 流程：先 Mermaid，后渲染

```
① 先在对话里写 Mermaid 源码（或 ASCII 草图）
        ↓
② 学生确认结构对不对
        ↓
③ 交给画图技能渲染
        ↓
④ 渲染图存 assets/，Mermaid 源码留在记录里
```

**为什么不能一步到位**：渲染图改不动，也没法审阅；Mermaid 是文本，能 diff、能校对、能回滚。
而且它逼你先想清结构——结构错了，渲染得再漂亮也是错的。

---

## 4. 三个落点

| 位置 | 画什么 | 频次 |
|---|---|---|
| **路径展示**（roadmap §8） | 大点依赖图：哪些串行、哪些有前置 | 一次，规划时 |
| **每日讲授**（daily §3） | 概念图：内存 / 时序 / 状态机 / 电路 | 一节最多 **1–2 张**，且必须命中 §1 判据 |
| **板块笔记**（notes §6） | 知识点关系图：这个板块里谁是谁的前置 | 可选，一个板块一张 |

---

## 5. 用哪个工具画（先分流，再调用）

**默认：archify** —— 它接受 Mermaid 输入，正好接上「先写 Mermaid 再渲染」的流程，而且会校验、能导出 PNG/SVG。

| 我们要的图 | 用什么 | 备注 |
|---|---|---|
| 学习路径依赖、算法步骤 | **archify** · Mermaid `flowchart` | 协议默认 |
| I²C / SPI 时序、中断响应 | **archify** · Mermaid `sequenceDiagram` | 时间关系 |
| 状态机（NVIC / 协议状态） | **archify** · Mermaid `stateDiagram` | |
| 内存布局 / 栈帧 / 结构体 | diagram-design 的 layer stack，或 archify 的框图 | 两者都可 |
| **电路原理图** | ❌ **都不用** | 用 LTspice / KiCad 截图，或 ASCII 草图 |
| **示波器波形** | ❌ **都不用** | 仿真截图，或用 matplotlib 画 |

**为什么必须分流**：架构图工具画不出反馈回路，也画不出上升沿。硬用它们画电路，
产出的东西**看起来像电路但不是电路**——比不画更糟，因为它会让学生记住一个错的拓扑。

技能名按环境里实际装的填，传给它的应该是：

| 传 | 不传 |
|---|---|
| Mermaid 源码 | 整段讲义 |
| 一句话目标（"给学生看栈帧怎么长出来"） | 十张图的清单 |
| 尺寸/主题要求（一屏能看完） | 你还没确认的结构 |

**产出**：
- 渲染图 → `assets/<记录号或KB号>-<用途>.png`
- Mermaid 源码 → 留在当日记录或板块笔记里，放在 ```mermaid` 围栏中

**记录里引用**：`![栈帧如何生长](../assets/01-栈帧.png)`
（记录在 `02-每日笔记/`，assets 在根目录，所以用 `../assets/`）

## 6. 反模式

- ❌ **每节课都画**——噪音，而且拖慢节奏
- ❌ **用图代替讲解**——图是补充，不是替代
- ❌ **装饰性流程图**——三个框两个箭头，去掉就什么也没丢
- ❌ **图里有正文没提的分支或数值**——学生会以图为准，然后就错了
- ❌ **只存渲染图不存源码**——改不了，也没法验证结构
- ❌ **不确认结构就渲染**——学生拿到一张错的图，比没有图更糟
- ❌ 把配图当成"显得专业"的手段

---

## 7. 和真实性闸门的关系

图属于**产物**，不是**证据**。所以：

- 图里的每个数值必须在正文/知识库里找得到出处
- 电路、时序类图必须与 KB 资料的具体章节核对（记下 `依据 KB01 的第 1.3 节`）
- 记录里标注「图为 AI 生成」——别让它看起来像是教材原图

## 8. 实测踩到的三件事（2026-10-23 时钟树验证）

用 STM32 时钟树跑通整条链路时踩到，写进来省得下次重踩：

1. **gate 全过 ≠ 图能看。**
   finalize 的四项检查全 pass，它仍然会报
   *"crossings or detours still need perceptual review"*。
   **必须导出一张 PNG 亲眼看一遍**——一行线的交叉、两个标签叠在一起，机器不判，学生一看就晕。

2. **重画前先清旧回执，否则会误判。**
   第二次 finalize 直接 fail，诊断是 `viewer/evidence-path-conflict`：
   browser-check 不肯覆盖上一轮留下的 `*.browser-check.json`。
   **这不是图错了**。处理：删掉旧的 `*.finalize*.json` / `*.browser-check.json`，
   或换一个新目录重跑。**别因为 exit=1 就去改内容**。

3. **一次请求一个目录**：`.archify/<type>-<slug>-<时间戳>/`。
   旧版本留着，学生可以对比"改前 / 改后"。

**验收动作固定成三步**：finalize（4 gates）→ 导 PNG → 自己看。

## 9. 一次合格的成品长什么样

时钟树那次的定稿：

- 只画**这次实际走的路径**（HSE → PLL ×9 → SYSCLK → AHB → HCLK → APB1/APB2），
  把「也可以直接用 HSI/HSE」这种旁支**写进卡片**，不画进图里
- 每个节点带频率和它挂的外设，图本身能替代一段文字
- 三张卡片分别是：怎么配 / 三条硬上限 / 三个坑
- 图里每个数字都能在头文件或手册里对上

**判据**：这张图如果去掉，学生会不会看不明白？会 → 值；不会 → 删掉。
