# 三轨笔记（notes）

**什么时候用**：归档时；学生说「记一下 / 这个有用」时；需要写板块笔记时；迁移旧档案时。

---

## 1. 三条轴，三套规则

| 文件 | 轴 | 内容 | 写入规则 |
|---|---|---|---|
| `00-学习档案.md` | 身份轴 | 契约 / 画像 / 看板 / 索引 | 画像只追加；看板可改；索引随记录增长 |
| `01-学习路径.md` | 主题轴 | 大点 / 完成标准 | 可改，但改完留痕 |
| `02-每日笔记/` | 时间轴 | 某天讲了什么、错在哪 | **只追加，一个字都不改** |
| `03-板块笔记/` | 知识轴 | 某个知识点现在怎么理解 | **反复重写**（理解变了就更新） |

分轨的理由：这三套规则互斥。合成一个文件，必然出现"改 A 的时候顺手美化了 B"。

---

## 2. 归档时机

**一轮循环结束后写一次，不是每句话之后。**

„一轮循环 = 讲授 → 实践 → 提问 → 出题 → 作答 → 讲评 → 重考/继续/停止„

**中途不要零散地写。** 但学生随时说「记一下」时，要**立刻**记进**本轮待归档缓存**，
并在回复里显式列出来给他看：

> 「记下了（本轮待归档）：① p+1 按 sizeof 缩放 ② 门牌号类比。课程结束一并写进档案。」

这样他当场能看到"没漏"，又不会把半截内容写进历史。

---

## 3. 归档的五件事

判断标准：**一个新 AI 只读这条记录，就知道这轮讲了什么、你错在哪、下次该做什么。**

| # | 做的事 | 说明 |
|---|---|---|
| 1 | **自动把学生的答案填进去** | 他说过的、贴过的，全部搬进记录。不许留空等他再填 |
| 2 | **自动收录他给的笔记** | 他说「记一下」的，原话进 **📌 学生笔记**，**一个字都不改** |
| 3 | **自动补全他漏掉的** | 答对但没说全、跑了但没解释、提到概念没讲清 → 进 **📎 遗漏补全**，标注"这是他没提到的" |
| 4 | **补齐所有空板块** | 任何「待填」都不能留，没内容写「本轮无」并写明 |
| 5 | **核对画像（T0）** | 每次正课归档的最后一步。有真变化 → 升一版并写变更日志；没变化 → 只更新看板「画像最后核对」。规则见 [profile.md](profile.md) |

## 4. 三种入口

### 4.1 📌 学生笔记（用户主动）

| 项 | 规定 |
|---|---|
| 触发 | 「记一下 / 这个有用 / 帮我存笔记 / 这个类比好」 |
| 时机 | **立刻**进待归档缓存，本轮结束写进当日记录 |
| 措辞 | **原样保留**，不改成教科书语言、不修病句、不合并 |
| 典型 | 「原来 &x 和 p 是同一个值」「指针 = 门牌号」 |

**为什么不改他的措辞**：他下次找线索时，是从**自己的话**里找的。你"整理"成标准表述，他就找不到了。

### 4.2 📎 遗漏补全（系统自动）

| 项 | 规定 |
|---|---|
| 触发 | 归档时 AI 自查 |
| 内容 | 他答对但没说全的、他跑了但没解释的、他提到但没讲清的 |
| 措辞 | AI 自己的话，且必须标注「他没提到的」 |
| 典型 | 「他答对了 p+1 是 4 字节，但没提到这是 sizeof(int) 决定的，下次重考要追这一点」 |

**两者的区别（最容易搞混）**：

| | 📌 学生笔记 | 📎 遗漏补全 |
|---|---|---|
| 谁的话 | 学生，原样 | AI，标注来源 |
| 能不能改 | ❌ 一个字都不改 | 这是 AI 写的 |
| 什么时候 | 他说「记一下」的那一刻 | 归档时自查 |

### 4.3 🧠 板块笔记（双写）

见 §5。

## 5. 双写：从当日记录沉淀到板块笔记

**这是原文档缺失的一环。** 原文档的 📌 和 📎 **只写进当日记录**，
附录里那份"按主题记的笔记"没有任何写入路径——所以它至今四个小节全是「待填」。

**判据（三条问，任一条成立就写）**：

1. **离开这道题仍然成立吗？** 是规律，还是这一步的算式
2. **下次遇到会想不起来吗？** 易错点 / 反直觉结论 / 命令口吻
3. **学生说过「记一下」吗？** 说了就一律双写，不再判断

**不写进去的**：题目细节、当次环境输出、一次性报错、以及任何"下次还能在当日记录里查到"的东西。

**当天记录里要留反向链接**，不然断链：

> `→ 已沉淀：03-板块笔记/内存与指针.md#按-sizeof-缩放`

## 6. 板块笔记格式

一个板块文件 = 一个主题，里面是一串**知识点条目**。条目是复习单位。

```
## 知识点：按 sizeof 缩放

> 状态 🟡 ｜ 上次复习 2026-10-22 ｜ 次数 2 ｜ 来源 记录 2

**一句话**：指针 +1 移动的字节数 = sizeof(指向类型)，不是 1 字节。

**为什么**：指针的算术单位是"元素"，不是"字节"。编译器在 p+1 处自动乘上 sizeof(*p)。

**易错**：只记住 int 是 4，没抽象成规律 → 遇到 char* 就答 4。

**判别动作**：看到指针做加减，先问"它指向什么类型"，再问"sizeof 是多少"。

**学生原话**：「差值是四个字节」
```

**元数据行是硬格式**（脚本靠它派生复习清单），**六段**：

```
> 状态 🔴 ｜ 上次复习 2026-10-22 ｜ 次数 1 ｜ 连对 0 ｜ 固化 — ｜ 来源 记录 1
```

| 段 | 合法值 | 含义 |
|---|---|---|
| 状态 | 🔴 生 / 🟡 半熟 / 🟢 稳 | **只允许这三个**；`✅` 不属于状态，属于「固化」 |
| 上次复习 | `YYYY-MM-DD` 或 `—` | `—` = 从没复习过。**不许预支**：没发生就写 `—` |
| 次数 | 整数 | **次数 = 1（讲授当次）+ 每次复习 1**。错题重考也算，同一天不重复计。**0 = 只备了课、还没讲**，不进复习货架 |
| 连对 | 整数 | 连续几次提问答对；答错归零。毕业判定用这个 |
| 固化 | `✅` 或 `—` | 毕业标记。固化后移出默认货架，学生点名还能复习 |
| 来源 | `记录 N` | N 必须真实存在，否则 lint 报错 |

**为什么次数从 1 起算**：这条知识点是"讲过一次"才被记下来的。从 0 起算会让毕业规则
（次数 ≥ 3）多要一次复习，两处口径一漂，规则就废了。

**条目里必须有「一句话」「易错」「学生原话」三块**——分别对应：
讲得清、记得住、找得回。

**可选**：当一个板块里的知识点存在明显的「谁是谁的前置」时，在板块文件开头挂一张关系图
（先 Mermaid 后渲染，见 [visuals.md](visuals.md)）。没有依赖关系就别画。

## 7. 记录索引与拆分

### 7.1 索引

每条新记录写完，**同步**在 `00-学习档案.md` 的「🗂 每日记录索引」加一行：

> `| 3 | 2026-10-22 | 按 sizeof 缩放 | 2/4 | 02-每日笔记/记录03-2026-10-22-按sizeof缩放.md |`

索引是接手的关键：新 AI 只读 00-学习档案.md + 索引最后 3 行，就能开工。

### 7.2 档案变长：压缩，不是无限追加

索引一行一条，一年 200 节课就是 200 行。**别让它无限长**，用压缩：

```bash
python scripts/study.py compact <学习目录>
```

规则（默认值，可用 --keep / --trigger 改）：

| 项 | 值 |
|---|---|
| 保留完整 | 最近 **40** 条 |
| 触发 | 记录满 **80** 条 |
| 动作 | 把**离现在最远的 40 条**移进 `02-每日笔记/_归档/批次-NN/` |

**移走 ≠ 删除。** 那 40 个文件一字未改，只是不再占索引行。

索引里换成一整行：

```
| 1–40 | 2026-01-02 ~ 2026-02-10 | 第 1 批（已压缩） | — | — | 02-每日笔记/_归档/批次-01/ |
```

每个批次目录里生成一份 `SUMMARY.md`：

- **统计是自动算的**（涉及大点、考核总题数、正确率、正确率最低的几条）——不推断
- **「综述」留给 AI 填** 3–5 行，并且写死一句：「只写上面统计能支撑的结论，没证据就写「无」」

**为什么留总结而不只留文件**：半年后没人会翻 40 个文件，但会读 5 行总结。
而总结必须有出处——所以统计自动生成、综述只准引用统计。

### 7.3 多计划：一个计划一个文件夹

```
~/学习档案/
  索引.md            ← 所有计划的清单（projects --write 生成）
  STM32/             ← 一个计划
  模电/              ← 另一个计划
```

**计划之间互不影响**：画像、看板、知识库、复习清单都是各管各的。
跨学科迁移（比如"他在模电学会的假设-验证法，STM32 里还用得上吗"）要靠人判断，脚本不做。

列出所有计划：

```bash
python scripts/study.py projects ~/学习档案 --write
```


## 8. 迁移已有档案（只搬不改）

学生已有一份单文件学习 md（例如那份 1253 行的 FPGA 路线），想接进本结构：

| 步骤 | 做什么 | 不许做什么 |
|---|---|---|
| 1 | **先备份**：复制一份到 `<目录>/_迁移前备份` | 直接在原文件上改 |
| 2 | 识别分区：协议段 / 画像 / 看板 / 路线 / 记录 | 用自己的话重写 |
| 3 | 协议段 → 进 `01-学习路径.md` 开头的「自定协议」节，标明"原文档协议，优先于本技能" | 丢掉原文档的硬规矩 |
| 4 | 画像 + 看板 + 契约 → `00-学习档案.md` | 美化历史条目 |
| 5 | 路线 → `01-学习路径.md` | 重排大点顺序 |
| 6 | 每条历史记录 → 单独文件放 `02-每日笔记/`，文件名带上原编号 | 改写记录内容 |
| 7 | 生成索引 | 漏行 |
| 8 | 原主题笔记 → `03-板块笔记/` | 把「待填」当内容搬过去 |

**迁移完必须对账**：记录数一致、编号连续、每条记录里的数字（分数/日期）一字不差。
对不上就回滚，别硬撑。

## 9. 五条规矩

1. **只追加，不改旧记录。** 历史是证据，不能美化。
2. **锚点唯一。** 记录编号不重复、不跳号。
3. **写完必须同步更新看板和索引**，否则下次读到过期状态。
4. **模板里不允许留「待填」。** 没内容写「本轮无」，也必须写明。
   **唯一例外**：还没问到的字段写 `待观察（第 1 次课补齐）`——这是合法占位，lint 放行；
   「待填」是偷懒，「待观察」是排期。
5. **学生的原话用引号原样保留**，不要"整理"成教科书语言。
